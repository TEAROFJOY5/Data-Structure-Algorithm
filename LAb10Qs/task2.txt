Task 2:
A tiny teaching operating system keeps a ready-queue of processes that are waiting to be given time on the CPU, and each process in this system is identified by a unique process identifier called a `pid` and carries a priority value where a larger number means the process is more important and should therefore be run sooner. During the design review of this scheduler, the engineering team explicitly rejected a linear-time insertion approach because the system is expected to stay responsive under heavy load, with many processes arriving and being dispatched continuously, so both the insertion of a newly arrived process and the removal of the next process to run must cost logarithmic time in the number of waiting processes. The scheduler therefore stores all waiting processes in a max-heap ordered by priority, implemented on top of a dynamically allocated array that grows automatically whenever it runs out of room, so that the most important process is always available at the root of the heap and can be dispatched immediately. It is important to note that, unlike the clinic triage queue in the previous task, this operating system does not promise any arrival-order fairness among processes that happen to have the same priority; the heap only guarantees that the process with the maximum priority is always at the root, and any two processes with equal priority may be dispatched in either order. Your job is to implement this max-heap based scheduler from scratch, making sure that it correctly maintains the heap property through both insertion and deletion, that it grows its internal storage correctly when full, and that it continues to behave correctly after several resizing operations, and then to demonstrate its behavior in `main` with a realistic sequence of process arrivals and dispatches.

Requirements:
You must first define a structure named `Process` containing two integer members, `pid` and `priority`, and then implement a class named `ProcessHeap` that is backed by a dynamically allocated array of `Process` objects declared as a member `Process* arr`, along with integer members `capacity` and `size` that track the allocated length of the array and the number of processes currently stored in it. Inside the class you must implement the private helper functions that make heap navigation possible: `int parent(int i)` returning `(i - 1) / 2`, `int leftChild(int i)` returning `2 * i + 1`, and `int rightChild(int i)` returning `2 * i + 2`, all using zero-based indexing as described in the lab manual; a `void swapProcess(Process& a, Process& b)` helper that exchanges two process records; and two sift functions `void heapifyUp(int i)` and `void heapifyDown(int i)` that both compare processes on their `priority` field, where `heapifyUp` repeatedly swaps a newly inserted element with its parent while the parent has a smaller priority, and `heapifyDown` repeatedly swaps an element with its larger child while that child has a greater priority than the element itself. The public interface must include a method `void addProcess(int pid, int priority)` that, when the array is already full, doubles the capacity by allocating a new array, copying every existing element into it, deleting the old array, and then continues with the insertion followed by `heapifyUp`; a method `int runNext()` that removes and returns the `pid` of the process at the root of the heap by replacing the root with the last element, decrementing the size, calling `heapifyDown` on the root, and then returning the removed `pid`, while printing an error message and returning `-1` if the heap is empty; a method `int peekNext()` that returns the `pid` stored at the root without removing it and returns `-1` with an error message if the heap is empty; a method `void display()` that prints the heap array in level order as `(pid, priority)` pairs followed by a newline; a method `bool isEmpty()` that reports whether the heap currently holds no processes; and a destructor that frees the dynamically allocated array so no memory is leaked. Finally, in `main`, you must add the processes `addProcess(1, 5)`, `addProcess(2, 9)`, `addProcess(3, 2)`, `addProcess(4, 9)`, and `addProcess(5, 7)`, then call `display()` to show the heap array; then repeatedly call `runNext()` until the heap is empty, printing each returned `pid` in the order produced; and then, to prove that the dynamic resize path actually works, you must create a second, freshly constructed empty `ProcessHeap` (preferably with a very small initial capacity such as two) and add eight processes to it so that the internal capacity is exceeded at least a few times during the sequence, printing the heap after every insertion or at sensible checkpoints so the growth can be observed.
